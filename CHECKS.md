## 1. When each check runs

```
write code
  -> editor: TypeScript + ESLint errors show while you type
  -> npm run lint         ESLint over the whole project
  -> npm run build        tsc -b (types) then vite build     (fails on a type error)
  -> npm run dev          port 5173 only; route tree regenerated on save
  -> git commit / push    no hooks yet in this repo (see section 9)
  -> pull request         CI not added yet (see section 9)
```

| Check | Tool | Runs | Blocks |
|---|---|---|---|
| Types | `tsc -b` | `npm run build`, editor | Yes: the build fails |
| Lint | ESLint | `npm run lint`, editor | Reports errors and warnings |
| Route links | TanStack Router types | Type check | A `<Link>` to a page that doesn't exist |
| Port | Vite `strictPort` | `npm run dev` | Starting on any port other than 5173 |
| Commit rules, formatting | husky + commitlint + Prettier | Not yet | Not yet |

**Important:** this repository has **no git hooks yet**. Until they are added, run `npm run lint` and `npm run build` yourself before every commit.

## 2. Type checks

| | |
|---|---|
| **Command** | `npx tsc -b` (also the first half of `npm run build`) |
| **Config** | `tsconfig.app.json` for `src/`, `tsconfig.node.json` for `vite.config.ts` |

What the settings catch:

| Setting | Catches |
|---|---|
| `strict` (on by default in TypeScript 6, not written in the file) | `null` / `undefined` not handled, implicit `any` |
| `noUnusedLocals` | Variables and imports you never use |
| `noUnusedParameters` | Function parameters you never use (name them `_name` if they must exist) |
| `noFallthroughCasesInSwitch` | A `case` that runs into the next one by mistake |
| `erasableSyntaxOnly` | TypeScript-only syntax that can't simply be removed (enums, parameter properties) |
| `verbatimModuleSyntax` | Type imports must say `import type`, so they disappear from the build |
| `paths` `@/*` | Imports through `@/` that point to a missing file |

**See it work:** write `const count: number = "1";` in `src/routes/index.tsx`, then run `npm run build`.

## 3. Lint (ESLint)

| | |
|---|---|
| **Command** | `npm run lint` |
| **Config** | `eslint.config.js` |

| Rule set | Catches |
|---|---|
| `@eslint/js` recommended | Unused variables, unreachable code, duplicate keys, `==` mistakes |
| `typescript-eslint` recommended | Unsafe `any`, wrong TypeScript patterns |
| `eslint-plugin-react-hooks` | Hooks called inside `if` or loops, missing effect dependencies, unsafe patterns |
| `eslint-plugin-react-refresh` (Vite config) | Files that break hot reload by exporting non-components next to components |

What is skipped, and why:

| Skipped | Why |
|---|---|
| `dist/` | Build output |
| `src/routeTree.gen.ts` | Generated by the router plugin |
| Fast-refresh rule in `src/components/ui/**` | shadcn files also export variants (`buttonVariants`) by design |
| Fast-refresh rule in `src/routes/**` | The TanStack plugin handles hot reload for route files itself |

## 4. Build

| | |
|---|---|
| **Command** | `npm run build` = `tsc -b && vite build` |
| **Checks** | Types first; if they fail, Vite never runs |
| **Output** | `dist/`: `index.html` + hashed JS and CSS files |
| **Then** | `npm run preview` serves `dist/` to test the real build |

The build needs `src/routeTree.gen.ts` **before** `tsc` runs, which is why that generated file is committed. If it were ignored, a fresh clone or CI would fail.

## 5. Typed routes

The `declare module '@tanstack/react-router'` block in `src/main.tsx` registers every route, so the type checker validates navigation:

| Code | Result |
|---|---|
| `<Link to="/login">` | OK |
| `<Link to="/loginn">` | Type error: no such route |
| `navigate({ to: "/skills/$id", params: { id: "1" } })` | OK |
| `navigate({ to: "/skills/$id" })` | Type error: `id` is missing |

Unknown URLs at runtime show the `NotFound` component from `__root.tsx` ("Page not found.").

## 6. Dev server checks

| Check | Setting | Why |
|---|---|---|
| Fixed port | `server: { port: 5173, strictPort: true }` | The API's CORS allows only `http://localhost:5173`. On another port every API call would fail with a confusing CORS error, so Vite stops instead |
| Route tree | Router plugin watches `src/routes/` | Adding or renaming a page file updates the routes immediately |
| Devtools | Router (bottom right) and Query (bottom left) | Inspect routes, cache and requests; removed from production builds |
| StrictMode | `<StrictMode>` in `main.tsx` | Renders twice in development to expose side-effect bugs |

## 7. Environment variables

| Rule | Why |
|---|---|
| Only `VITE_` variables reach the browser | Vite exposes them on purpose |
| **Never put a secret in a `VITE_` variable** | Everything in the browser bundle can be read by anyone |
| `.env` is ignored, `.env.example` is committed | Local values stay local; others see which variables exist |

## 8. Git and repository protections

| Protection | File / place | Stops |
|---|---|---|
| Secret files ignored | `.gitignore`: `.env`, `.env.*` (but not `.env.example`), `*.local` | Keys reaching GitHub |
| Build output ignored | `.gitignore`: `node_modules`, `dist`, `dist-ssr`, logs | Huge or generated files in git |
| Editor folders ignored | `.gitignore`: `.vscode/*` (except `extensions.json`), `.idea`, `.DS_Store` | Personal settings in git |
| Line endings | `.gitattributes`: `* text=auto eol=lf` | Windows CRLF changes in every file |
| Exact installs | `package-lock.json` committed | Version differences between machines |
| Branch rule on `main` (GitHub settings) | Require a pull request, block force pushes | Direct pushes to `main` |
| Dependabot + secret scanning (GitHub settings) | Alerts and push protection | Vulnerable packages, leaked keys |

## 10. Manual checklist before a pull request

- [ ] Branch name follows the type: `feat/skills-page`, `fix/login-redirect`, `chore/husky`
- [ ] `npm run lint` has no errors
- [ ] `npm run build` passes
- [ ] Opened the page in the browser with the API running, and clicked through it
- [ ] Loading, error and empty states all look right
- [ ] Works at phone width (about 375 px)
- [ ] No `console.log` left
- [ ] No secret in any `VITE_` variable; `git status` shows no `.env`
- [ ] README / STACK / CHECKS updated if something changed
- [ ] PR description in English: what, why, how it was tested, a screenshot for UI changes

---

## 11. Manual checklist for a new page or feature

- [ ] Page file in `src/routes/` (one file = one route)
- [ ] Feature code in `src/features/<name>/`: `api.ts`, `hooks.ts`, `components/`, `types.ts`
- [ ] Data read with `useQuery`, written with `useMutation`, list refreshed with `invalidateQueries`
- [ ] No data fetching in `useEffect`
- [ ] Imports through `@/`
- [ ] shadcn components used before writing new ones (`npx shadcn@latest add <name>`)
- [ ] Styles with Tailwind classes; colours from the theme variables (`bg-primary`, `text-muted-foreground`), not hard-coded hex values
- [ ] Forms with React Hook Form + Zod, errors shown under the fields
- [ ] Links use `<Link to="...">` so they're type-checked
- [ ] Shared code goes to `components/` or `lib/` only when two or more features use it
